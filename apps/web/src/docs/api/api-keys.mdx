# API Keys

These endpoints let you manage API keys for a workspace programmatically. All endpoints require a valid **session cookie** — they're for dashboard use, not for use with an API key itself.

Keys are workspace-scoped. A key created here can only authenticate requests against the workspace it belongs to.

---

## List keys

Returns all active API keys for a workspace. Secrets are never included — only the preview (last 4 characters of the raw token).

```http
GET /api/v1/workspaces/:identifier/api-keys
Cookie: <session>
```

**Response — `200 OK`**

```json
{
  "keys": [
    {
      "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "name": "Main production server",
      "type": "general",
      "keyPreview": "orb_api_...a3f2",
      "createdAt": "2025-01-15T10:00:00.000Z",
      "lastUsedAt": "2025-05-26T14:30:00.000Z"
    },
    {
      "id": "b2c3d4e5-f6a7-8901-bcde-f12345678901",
      "name": "FiveM RP Server",
      "type": "voyager_fivem",
      "keyPreview": "orb_voy_...9f1a",
      "createdAt": "2025-02-10T08:00:00.000Z",
      "lastUsedAt": null
    }
  ]
}
```

| Field | Description |
| --- | --- |
| `id` | Unique key ID — use this to revoke the key |
| `name` | The name you gave the key |
| `type` | `general` or `voyager_fivem` |
| `keyPreview` | Partial preview of the key for identification (never the full secret) |
| `createdAt` | ISO 8601 timestamp of when the key was created |
| `lastUsedAt` | ISO 8601 timestamp of last use, or `null` if never used |

## Create a key

Creates a new API key for the workspace. The full secret is returned **only in this response** — it cannot be retrieved again.

```http
POST /api/v1/workspaces/:identifier/api-keys
Cookie: <session>
Content-Type: application/json

{
  "name": "Main production server",
  "type": "general"
}
```

**Request body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | ✓ | A label for the key (1–100 characters) |
| `type` | string | ✓ | `general` or `voyager_fivem` |

**Response — `201 Created`**

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "name": "Main production server",
  "type": "general",
  "keyPreview": "orb_api_...a3f2",
  "createdAt": "2025-01-15T10:00:00.000Z",
  "secretKey": "orb_api_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
}
```

> **Store this now.** The `secretKey` is hashed immediately after creation and cannot be retrieved later. If you lose it, revoke the key and create a new one.

**Key prefixes by type**

| Type | Prefix |
| --- | --- |
| `general` | `orb_api_` |
| `voyager_fivem` | `orb_voy_` |

## Revoke a key

Permanently deletes a key. Revocation is immediate — the key will return `401` on the very next request.

```http
DELETE /api/v1/workspaces/:identifier/api-keys/:keyId
Cookie: <session>
```

Use the `id` field from the list or create response as `:keyId`.

**Response — `200 OK`**

```json
{ "ok": true }
```

There is no undo. If you need the integration to keep working, create a new key before revoking the old one and rotate it in your server's configuration.

---

## Security tips

- **Never commit keys to source control.** Store them in environment variables or a secrets manager.
- **Use one key per integration.** This makes it easy to revoke a single key if a server is compromised without affecting others.
- **Rotate keys periodically.** Create a replacement, update your config, then revoke the old one.
- **Use Voyager keys for Voyager.** Keeping key types separate makes auditing usage easier.
